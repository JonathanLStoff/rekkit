# Starting a session (the main agent)

For the agent a person starts on this repository (agy, Claude Code, Codex, Cursor, Gemini CLI, Copilot…). Role subagents skip this file: their prompt and role file are all they need. The rules are in `AGENTS.md`; commands and architecture in `.agents/reference.md` (or `make help`).

## Steps

Do these in order, without waiting to be told.

1. **Check the setup.** Run `./setup.sh --check` (Windows: `setup.cmd --check`; any OS: `make doctor`) and read its summary.
   - Exit `0`: ready. Go to step 2.
   - Exit `3`: run `./setup.sh` (it does every `·` line itself), then read the summary again.
   - Exit `1`: a `✗` line failed. If the fix is a command you are allowed to run, run it and re-run `./setup.sh`. If it needs an install the user must approve (`sudo`, Homebrew, winget, rustup, a JDK), tell the user the exact command from the `✗` line.
   - Exit `2`: the `!` lines need a person. **Tell the user, word for word, what each `!` line says to download or do.** Usually that is: install the official Minecraft launcher, sign in, play version 26.3 once, then run `./setup.sh` again. Then **keep working**: everything except the live game test (step 7 of the lifecycle) works without it.
2. **Pick the work.** Progress lives in **Beads** (`bd`; `bd prime` shows the state, and agy and Claude Code run it at session start). Take the mod whose epic is in progress (`make fleet-status`), else the first ready epic (`bd ready --type epic`). The order is: `rekkit_core`, then the mods in `planning/priority.md` order, then the other Tekkit mods, then Direwolf20, then Agrarian Skies 2. `planning/fleet-board.md` shows it, generated by `make board`; never edit the board by hand.
3. **Do it, to the end.** Read `.agents/agents/conductor/agent.md` and act as the conductor: its first command is `make fleet-start MOD=<id>`, then it runs the 11 steps (`planning/workflow.md` §2):
   1 Spec from the decompiled Java → 2 Scaffold → 3 Code (from the spec only) → 4 Check (syntax and logic) → 5 Extract the original assets (beside 2–4) → 6 New assets, only for what the original never had, at its resolution and style → 7 Recheck everything → 8 the live harness: every block placed without a crash or a single warning → 9 Package. Then the mod is **complete and ready for a human**, and your last message starts with `DONE, CHECK OUT THE PROGRESS: make play MOD=<id>`.
   Where the conductor *invokes* a role, start that role as a subagent if your tool can (see *Your tool* below); otherwise do the role yourself by reading `.agents/agents/<role>/agent.md`. Read the skills a role lists (`.agents/skills/<name>/SKILL.md`) before its work.
   **Do not stop until step 9 is closed.** Never end your turn to report progress, summarise, or ask whether to continue: go on to the next step. Wait for subagents you started and file their reports (`make fleet-inbox`); do not end your turn while they run. The only other reasons to stop: the user tells you to (or ran `make fleet-stop`), or something only a person can fix blocks the mod. Then set its epic to `blocked` with the reason as a comment, tell the user exactly what they need to do, and stop. In agy and Claude Code the stop hook holds you to this.
4. **Record it.** The conductor alone writes to Beads: it closes each story and feature as it is done, files every subagent report (`make fleet-inbox`), and runs `make board`. A role subagent starts with `make fleet-task BEAD=<id> ROLE=<role>` and ends by writing its report to `target/fleet/inbox/<bead>.json`; it never runs `bd create/update/close`.
5. **Before you stop.** `make agent-gate MOD=<id>` passes (rustfmt, clippy `-D warnings`, tests, check-mods, harness dry run). If Horizon itself is broken at the pinned revision (`make horizon-status`), that is filed as a `horizon` bug and does not hold the mod up.

## Your tool

`.agents/` is the one source for roles, skills and hooks. Edit it there, never in a tool's copy, then run `make agents` to regenerate the copies (`make agents-check` reports drift; `./setup.sh` does both).

| Tool | Reads | Roles (subagents) | Skills | Guards and stop gate |
|---|---|---|---|---|
| agy (Antigravity): start it with `make agy` (its terminal sandbox off; plain `agy` cannot reach the network, Beads or the game) | `AGENTS.md` | `.agents/agents/` (`/agents` → conductor) | `.agents/skills/` | `.agents/hooks.json` (with `bd prime` at session start) |
| Claude Code | `CLAUDE.md` → this file | `.claude/agents/` (generated); `/conductor` starts a run | `.claude/skills/` (generated) | `.claude/settings.json` hooks (generated; `bd prime` at session start, the gate on Stop and SubagentStop) |
| Codex, Cursor, Copilot, Gemini CLI (`GEMINI.md`), others | `AGENTS.md` | play each role yourself from `.agents/agents/<role>/agent.md`, or use your tool's subagents with that file as the prompt | read `.agents/skills/<name>/SKILL.md` by path | follow *Rules* yourself; run `bd prime` first and `make agent-gate` before you stop |

Model tiers in the roster: `pro` is your tool's strongest model, `flash` its fast one; in Claude Code `pro` roles run on the session's own model (`.agents/models.json`). Any model will do: when one hits a quota, usage or rate limit, nothing is lost. Restart a subagent that hit one on another model, or do its role yourself; never stop for it.

Headless, one mod per run, any tool: `make fleet-next` (or `AGENT_CMD="<cli and flags>"` for another tool); see `.agents/fleet-plan.md` §9. It works down the model chain in `.agents/models.json` across every installed tool (`AGENT=agy|claude|codex` tries that one first): a model that hits a limit rests until its reset and the mod continues on the next (`make fleet-models` shows which are resting).

## What only a person can do

| Thing | Why |
|---|---|
| Own Minecraft: Java Edition and play 26.3 once in the official launcher | Horizon builds its game resources from the player's own copy and never downloads it |
| Approve system installs (`sudo`, Homebrew, winget, rustup, JDK 25) | They change the user's machine |
| Playing the finished mod (`make play MOD=<id>`), reviewing it, `git push`, approving a release in the `mod-release` environment, listing a mod at playhorizon.dev/mods/submit | The hand-off, and outward-facing |
| Editing `planning/harness-allowed-warnings.txt` | Which warnings are acceptable is a person's call |
| A CurseForge API key (optional) | Without one, Agrarian Skies 2 uses the public 2.0.6 download |
