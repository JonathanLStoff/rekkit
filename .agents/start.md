# Starting a session (the main agent)

For the agent a person starts on this repository (agy, Claude Code, Codex, Cursor, Gemini CLI, Copilot…). Role subagents skip this file: their prompt, role file and brief are all they need. The rules every agent follows are in `AGENTS.md`; the main session's and the conductor's are below; commands and architecture in `.agents/reference.md` (or `make help`).

## Steps

Do these in order, without waiting to be told.

1. **Check the setup.** Run `./setup.sh --check` (Windows: `setup.cmd --check`; any OS: `make doctor`) and read its summary.
   - Exit `0`: ready. Go to step 2.
   - Exit `3`: run `./setup.sh` (it does every `·` line itself), then read the summary again.
   - Exit `1`: a `✗` line failed. If the fix is a command you are allowed to run, run it and re-run `./setup.sh`. If it needs an install the user must approve (`sudo`, Homebrew, winget, rustup, a JDK), tell the user the exact command from the `✗` line.
   - Exit `2`: the `!` lines need a person. **Tell the user, word for word, what each `!` line says to download or do.** Usually that is: install the official Minecraft launcher, sign in, play version 26.3 once, then run `./setup.sh` again. Then **keep working**: everything except the live game test (step 7 of the lifecycle) works without it.
2. **Pick the work.** Progress lives in the **issue tracker** (`issues/`, managed with `issuectl`). Its state is already in your context: agy, Claude Code and opencode put the tracker's context (and, while a mod is in progress, its resume page) there at session start and after compaction, so do not load the issues by hand. Take the mod whose epic is in progress (`make fleet-status`), else the first ready epic (`issuectl dag`). The order is: `rekkit_core`, then the mods in `planning/priority.md` order, then the other Tekkit mods, then Direwolf20, then Agrarian Skies 2. `planning/fleet-board.md` shows it, generated by `make board`; never edit the board by hand.
3. **Do it, to the end.** Read `.agents/agents/conductor/agent.md` and act as the conductor: it reads each step's detail with `make conductor-step STEP=<n>`, starts with `make fleet-start MOD=<id>`, then runs the 11 steps (`planning/workflow.md` §2):
   1 Spec from the decompiled Java → 2 Scaffold → 3 Code (from the spec only) → 4 Check (syntax and logic) → 5 Extract the original assets (beside 2–4) → 6 New assets, only for what the original never had, at its resolution and style → 7 Recheck everything → 8 the live harness: every block placed without a crash or a single warning → 9 Package. Then the mod is **complete and ready for a human**, and your last message starts with `DONE, CHECK OUT THE PROGRESS: make play MOD=<id>`.
   Where the conductor *invokes* a role, start that role as a subagent if your tool can (see *Your tool* below); otherwise do the role yourself by reading `.agents/agents/<role>/agent.md`. Read a role's skills by section (`make skill-show SKILL=<name> SECTION="<heading>"`).
   **Do not stop until step 9 is closed.** Never end your turn to report progress, summarise, or ask whether to continue: go on to the next step. Wait for subagents you started and file their reports (`make fleet-inbox`); do not end your turn while they run. The only other reasons to stop: the user tells you to (or ran `make fleet-stop`), something only a person can fix blocks the mod, or the model ran out of quota. Then set its epic to `blocked` with the reason as a comment (not for a quota), tell the user exactly what they need to do, and stop. In agy and Claude Code the stop hook holds you to this.
4. **Record it.** The conductor alone writes to the tracker: it closes each task as it is done, files every subagent report (`make fleet-inbox`), and runs `make board`. A role subagent starts with `make fleet-task BEAD=<id> ROLE=<role>` and ends by writing its report to `target/fleet/inbox/<bead>.json`; it never runs `issuectl`.
5. **Before you stop.** `make agent-gate MOD=<id>` passes (rustfmt, clippy `-D warnings`, tests, check-mods, harness dry run). If Horizon itself is broken at the pinned revision (`make horizon-status`), that is filed as a `horizon` bug and does not hold the mod up.

## Rules for the main session and the conductor

- **One mod at a time.** Never start a second epic while one is in progress. `rekkit_core` is the exception that is never started on its own: shared code a mod needs is filed under it (`make core-need`) and built during that mod's run, so the core grows with the mods.
- **Several versions: merge, newer wins.** When a mod ships in more than one pack (RedPower 2.0pr5b2 in Tekkit 1.2.5 and 2.0pr6 in Direwolf20 1.4.7), the port is the union of every version: each block, item, recipe and system any version has. Where versions share a feature, the newest version's behaviour, numbers and art win; a feature only an older version has stays, as that version made it. One epic and one mod per original mod, never one per version (the mod-spec skill).
- **Tickets, small and ordered, and few tokens.** A spec-writer per part (`make fleet-parts`) reads its part of the decompiled code once and writes its outline, its attributes and its tickets, each aimed at ~200k tokens of work and at most 6 files and 8 spec sections plus Java members (`make fleet-tickets` merges, validates and files them). `make fleet-dispatch MOD=<id>` then works the ready tickets with fresh headless agents, at most 2 at a time and a role's first ticket alone, files the reports and records each agent's tokens (`target/fleet/usage.jsonl`); it hands back only what needs the conductor or a person. An agent wraps up at 60 turns or 500k tokens billed; a ticket two agents could not finish is labelled needs-split and split, never started a third time. The conductor's own context: nearing its limit, it waits for in-flight work, files it, clears itself and continues with `make fleet-resume`, without a person.
- **Checkpoints.** A role subagent appends one line to `target/fleet/progress/<bead>.md` after each piece it finishes (`make fleet-task` says so and shows an interrupted predecessor's work). A conductor taking over runs `make fleet-resume MOD=<id>` (`make fleet-start` prints it) and restarts interrupted subagents rather than their steps.
- **Models: the one the person picked.** Every agent, role and headless run uses the model the tool is on; a role only sets its thinking level (`effort:` in its role file). A quota or rate limit stops the run and says when the model is back; only `FALLBACK=1` (a person's choice) goes on with another model from `.agents/models.json`.
- **Flat mode** (`REKKIT_FLAT=1` in `.env` or the environment; `make fleet-flat MODE=on|off|status`): no subagents in any tool, to save tokens. Every subagent pays the tool's fixed floor on every turn, so the one session you started does every role itself, linearly: `make fleet-ready MOD=<id>`, `make fleet-task BEAD=<id> ROLE=<role>` (its brief; it does not make you a role subagent, and you keep the tracker), do the ticket from `.agents/agents/<role>/agent.md`, write the report to `target/fleet/inbox/<bead>.json`, `make fleet-inbox`, next ticket. The spawn hook denies Agent/Task/invoke_subagent/subagent, `make fleet-dispatch` starts nothing (exit 3), and the 60-turn/500k cap, which counts a subagent, does not apply: keep your own context small (read each brief once, never earlier tickets' files; `make fleet-resume` after a compaction).
- **Subagents: only Claude, grok and agy run them.** **Local models never do, ever**: opencode (on any model, local or cloud), or any tool on Ollama, LM Studio or llama.cpp. The one session runs on the model opencode has selected (`/conductor`) and does every role itself, one ticket at a time, from `.agents/agents/<role>/agent.md`, still writing each report to `target/fleet/inbox/`. The opencode plugin blocks its `subagent` tool (and the older `task`) unless the operator sets `REKKIT_ALLOW_SUBAGENTS=1` in a session on a cloud model; never set it for a local model. `make fleet-local` always reports 0 subagents, and `make fleet-dispatch` refuses opencode (and any local model).
- **Native bundles** (`native/mixins/<id>/horizon-mixin.toml`) take only `id`, `version`, `priority` under `[mod]` and need at least one `[[injection]]`; `make check-mods MOD=<id>` enforces what `horizon-mixins` enforces. An engine gap is a bug labelled `horizon`.
- **Complete** = steps 1–9 closed: `make agent-gate MOD=<id>`, `make check-mods MOD=<id> COMPLETE=1`, parity-critic's Check and Recheck, and the live harness (`make e2e-mod MOD=<id>` and `make e2e-all-mods`: every block placed by `/setblock` and by a player in every variant, every item found in the mod's creative tabs, no WARN/ERROR beyond `planning/harness-allowed-warnings.txt`, which only a person edits). Every attribute of the outline (`planning/mods/<id>.features.json`) has a test level and a scenario of that level that passes (1 placement & hitbox, 2 item use, 3 block function, 4 interaction, 5 persistence, 6 automation & sides, 7 all mods together); `make contract-check MOD=<id>` compares models and textures with the original's pixels and `make fleet-contract MOD=<id>` files each difference; the stop hook holds the mod open while any remains.
- New art only for what the original never had (`make fleet-gaps`): SVG or `.pixels` in `mods/<id>/art/`, built by `make art MOD=<id>` at the original's size and palette. The art and sound are the original's until replaced; see `.agents/release.md`.
- **Versions bump themselves.** When a mod or `rekkit_core` changes, `make version-sync` (run by the stop gate, `make fleet-inbox` and `make agent-gate`) moves it one patch version past its last commit, in lockstep across `Cargo.toml`, `content/horizon-mod.toml`, `native/horizon-native.json` and `native/mixins/<id>/horizon-mixin.toml` (the core: its `Cargo.toml`). Work done before the next commit is bundled into that same version.
- The Makefile picks Python 3.11+ itself; outside make use `$(scripts/fleet/python.sh)`. Releases are signed and published by `.github/workflows/release-mods.yml` after a human pushes.
- **Where things are, cheaply:** `make fleet-context MOD=<id>` (state, spec, original archives in every pack, decompiled folders, files); `make spec-toc`/`spec-show`; `make java-outline DIR=<decompiled> [GREP=<name>]` then `java-show`; `make skill-toc`/`skill-show`; `make conductor-step STEP=<n>`. Long command output: keep the end (`2>&1 | tail -40`). Done means stop: no recap.

## Your tool

`.agents/` is the one source for roles, skills and hooks. Edit it there, never in a tool's copy, then run `make agents` to regenerate the copies (`make agents-check` reports drift; `./setup.sh` does both).

| Tool | Reads | Roles (subagents) | Skills | Guards, tracker context and stop gate |
|---|---|---|---|---|
| agy (Antigravity): start it with `make agy` (its terminal sandbox off; plain `agy` cannot reach the network, the issues or the game) | `AGENTS.md` | `.agents/agents/` (`/agents` → conductor) | `.agents/skills/` | `.agents/hooks.json` (the tracker context at session start) |
| Claude Code | `CLAUDE.md` → this file | `.claude/agents/` (generated); `/conductor` starts a run | `.claude/skills/` (generated) | `.claude/settings.json` hooks (generated; the tracker context at session start and after compaction, the gate on Stop and SubagentStop) |
| opencode (cloud or local models): `opencode` in the repo, pick the model, `/conductor` | `AGENTS.md` | `.opencode/agent/` (generated; subagents run on the selected model) | read `.agents/skills/<name>/SKILL.md` by section | `.opencode/plugin/rekkit-guard.js` (generated: the shell, paths and read guards, and the tracker context in the main session's system prompt and on compaction); no stop gate: the conductor keeps going itself. On a local model: no subagents, ever |
| Codex, Cursor, Copilot, Gemini CLI (`GEMINI.md`), others | `AGENTS.md` | play each role yourself from `.agents/agents/<role>/agent.md`, or use your tool's subagents with that file as the prompt | read `.agents/skills/<name>/SKILL.md` by section | follow the rules yourself; read the tracker's context first (`issuectl dag`; these tools have no session-start hook) and `make agent-gate` before you stop |

Headless, one mod per run, any tool: `make fleet-next` (or `AGENT_CMD="<cli and flags>"` for another tool); see `.agents/fleet-plan.md` §9. It runs on the model the tool is on and stops when that model runs out of quota (`FALLBACK=1`: down the chain in `.agents/models.json`; `make fleet-models` shows which are resting).

## What only a person can do

| Thing | Why |
|---|---|
| Own Minecraft: Java Edition and play 26.3 once in the official launcher | Horizon builds its game resources from the player's own copy and never downloads it |
| Approve system installs (`sudo`, Homebrew, winget, rustup, JDK 25) | They change the user's machine |
| Pick the model (start the session on it), and say `FALLBACK=1` | The quota is theirs |
| Playing the finished mod (`make play MOD=<id>`), reviewing it, `git push`, approving a release in the `mod-release` environment, listing a mod at playhorizon.dev/mods/submit | The hand-off, and outward-facing |
| Editing `planning/harness-allowed-warnings.txt` | Which warnings are acceptable is a person's call |
| A CurseForge API key (optional) | Without one, Agrarian Skies 2 uses the public 2.0.6 download |
