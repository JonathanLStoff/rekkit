# Rekkit agent rules

Rekkit ports Java Minecraft mods (Tekkit Classic 1.2.5, Direwolf20 1.4.7, Agrarian Skies 2) to Rust mods for the Horizon engine. Every agent, in any tool (agy, Claude Code, Codex, Cursor, Gemini CLI, Copilot…), follows this file. `CLAUDE.md` and `GEMINI.md` only point here.

## Start of every session

Do these in order, without waiting to be told.

1. **Check the setup.** Run `./setup.sh --check` (Windows: `setup.cmd --check`; any OS: `make doctor`) and read its summary.
   - Exit `0`: ready. Go to step 2.
   - Exit `3`: run `./setup.sh` (it does every `·` line itself), then read the summary again.
   - Exit `1`: a `✗` line failed. If the fix is a command you are allowed to run, run it and re-run `./setup.sh`. If it needs an install the user must approve (`sudo`, Homebrew, winget, rustup, a JDK), tell the user the exact command from the `✗` line.
   - Exit `2`: the `!` lines need a person. **Tell the user, word for word, what each `!` line says to download or do.** Usually that is: install the official Minecraft launcher, sign in, play version 26.3 once, then run `./setup.sh` again. Then **keep working**: everything except the live game test (step 7 of the lifecycle) works without it.
2. **Pick the work.** Progress lives in **Beads** (`bd`; `bd prime` shows the state, and agy and Claude Code run it at session start). Take the mod whose epic is in progress (`make fleet-status`), else the first ready epic (`bd ready --type epic`). The order is: `rekkit_core`, then the mods in `planning/priority.md` order, then the other Tekkit mods, then Direwolf20, then Agrarian Skies 2. `planning/fleet-board.md` shows it, generated by `make board`; never edit the board by hand.
3. **Do it, to the end.** Read `.agents/agents/conductor/agent.md` and act as the conductor: its first command is `make fleet-start MOD=<id>`, then it runs the 11 steps (`planning/workflow.md` §2):
   1 Spec from the decompiled Java → 2 Scaffold → 3 Code (from the spec only) → 4 Check (syntax and logic) → 5 Extract the original assets (beside 2–4) → 6 New assets, only for what the original never had, at its resolution and style → 7 Recheck everything → 8 the live harness: every block placed without a crash or a single warning → 9 Package. Then the mod is **complete and ready for a human**, and your last message starts with `DONE, CHECK OUT THE PROGRESS: make play MOD=<id>`.
   Where the conductor *invokes* a role, start that role as a subagent if your tool can (see *Your tool*); otherwise do the role yourself by reading `.agents/agents/<role>/agent.md`. Read the skills a role lists (`.agents/skills/<name>/SKILL.md`) before its work.
   **Do not stop until step 9 is closed.** Never end your turn to report progress, summarise, or ask whether to continue: go on to the next step. Wait for subagents you started and file their reports (`make fleet-inbox`); do not end your turn while they run. The only other reasons to stop: the user tells you to (or ran `make fleet-stop`), or something only a person can fix blocks the mod. Then set its epic to `blocked` with the reason as a comment, tell the user exactly what they need to do, and stop. In agy and Claude Code the stop hook holds you to this.
4. **Record it.** The conductor alone writes to Beads: it closes each story and feature as it is done, files every subagent report (`make fleet-inbox`), and runs `make board`. A role subagent starts with `make fleet-task BEAD=<id> ROLE=<role>` and ends by writing its report to `target/fleet/inbox/<bead>.json`; it never runs `bd create/update/close`.
5. **Before you stop.** `make agent-gate MOD=<id>` passes (rustfmt, clippy `-D warnings`, tests, check-mods, harness dry run). If Horizon itself is broken at the pinned revision (`make horizon-status`), that is filed as a `horizon` bug and does not hold the mod up.

## Your tool

`.agents/` is the one source for roles, skills and hooks. Edit it there, never in a tool's copy, then run `make agents` to regenerate the copies (`make agents-check` reports drift; `./setup.sh` does both).

| Tool | Reads | Roles (subagents) | Skills | Guards and stop gate |
|---|---|---|---|---|
| agy (Antigravity) | `AGENTS.md` | `.agents/agents/` (`/agents` → conductor) | `.agents/skills/` | `.agents/hooks.json` (with `bd prime` at session start) |
| Claude Code | `CLAUDE.md` → this file | `.claude/agents/` (generated); `/conductor` starts a run | `.claude/skills/` (generated) | `.claude/settings.json` hooks (generated; `bd prime` at session start, the gate on Stop and SubagentStop) |
| Codex, Cursor, Copilot, Gemini CLI (`GEMINI.md`), others | `AGENTS.md` | play each role yourself from `.agents/agents/<role>/agent.md`, or use your tool's subagents with that file as the prompt | read `.agents/skills/<name>/SKILL.md` by path | follow *Rules* yourself; run `bd prime` first and `make agent-gate` before you stop |

Model tiers in the roster: `pro` is your tool's strongest model (agy: Gemini 4 Argon, Claude Code: Opus), `flash` its fast one (agy: 3.8 Flash, Claude Code: Sonnet).

Headless, one mod per run, any tool: `make fleet-next AGENT=agy|claude|codex` (or `AGENT_CMD="<cli and flags>"` for another tool); see `.agents/fleet-plan.md` §9.

## Rules

- One mod at a time. Never start a second epic while one is in progress.
- **Clean-room.** Only the spec-writer, parity-critic, scout and conductor read the decompiled original (`assets/decompiled/`, from `make decompile`; never committed). Builders work from `planning/mods/<id>.md` alone and the hooks block them from the Java. The art and sound are the original's until replaced; see `.agents/release.md`.
- Template: `mods/example_mod`. Copy its shape; do not invent new layouts.
- Shared code lives in `crates/rekkit_core` (not under `mods/`). Use it instead of redefining energy, stacks, tanks, grids, side config, multiblocks or frequency keys.
- Never put `Cargo.toml` or `.rs` files under `mods/<id>/content/`.
- Native bundles (`native/mixins/<id>/horizon-mixin.toml`) take only `id`, `version`, `priority` under `[mod]` and need at least one `[[injection]]`; `make check-mods` enforces what `horizon-mixins` enforces.
- Never edit `horizon/` (git submodule). An engine gap is a Beads bug labelled `horizon` (subagents: a follow_up in the report).
- Every native hook checks its own namespace (`<id>:`) before acting.
- Only edit paths you own (`.agents/fleet-plan.md` §3). Report anything else to the conductor.
- Complete = steps 1–9 closed: `make agent-gate MOD=<id>`, `make check-mods MOD=<id> COMPLETE=1`, parity-critic's Check and Recheck, and the live harness (`make e2e-mod MOD=<id>` and `make e2e-all-mods`: every block placed by `/setblock` and by a player in every variant, no WARN/ERROR beyond `planning/harness-allowed-warnings.txt`, which only a person edits).
- New art only for what the original never had (`make fleet-gaps`): SVG or `.pixels` in `mods/<id>/art/`, built by `make art MOD=<id>` at the original's size and palette.
- The Makefile picks Python 3.11+ itself; outside make use `$(scripts/fleet/python.sh)`.
- Never `git push`, `gh release`, `minisign`, change the submodule, `git reset --hard`, `--force` or `rm -rf`. A human does those (the hooks in agy and Claude Code block them; elsewhere it is on you). Releases are signed and published by `.github/workflows/release-mods.yml` after a human pushes.
- Versions move in lockstep across `Cargo.toml`, `content/horizon-mod.toml`, `native/horizon-native.json` and `native/mixins/<id>/horizon-mixin.toml`. A mod whose `content/`, `native/` or `src/` changed since its last release needs a new version (`python3 scripts/release_plan.py --exclude example_mod`).

## What only a person can do

| Thing | Why |
|---|---|
| Own Minecraft: Java Edition and play 26.3 once in the official launcher | Horizon builds its game resources from the player's own copy and never downloads it |
| Approve system installs (`sudo`, Homebrew, winget, rustup, JDK 25) | They change the user's machine |
| Playing the finished mod (`make play MOD=<id>`), reviewing it, `git push`, approving a release in the `mod-release` environment, listing a mod at playhorizon.dev/mods/submit | The hand-off, and outward-facing |
| Editing `planning/harness-allowed-warnings.txt` | Which warnings are acceptable is a person's call |
| A CurseForge API key (optional) | Without one, Agrarian Skies 2 uses the public 2.0.6 download |

## Project reference

### Architecture: Horizon dual-artifact mods (no WebAssembly)

Every mod in `mods/<id>/` is three parts:

1. **Content mod (`.hmod`, API `0.2`, `capabilities = ["registries"]`)**: data and assets only (`content/horizon-mod.toml`, `content/data/`, `content/assets/`): blocks (with optional item `components`), items (with optional `crafting_remainder`), custom `mob_effect` types, recipes (including custom machine recipe types), loot tables, tags, models and textures. No code: `cargo-horizon-mod` rejects a `content/` with a `Cargo.toml`.
2. **Native mod (`.hnmod`, `NATIVE_HOOKS_API = 40`)**: a source-level [horizon-mixins](https://github.com/horizon-rust/horizon-mixins) bundle (`native/horizon-native.json` + `native/mixins/<id>/horizon-mixin.toml` + `.rs` helpers) hooking into `horizon/crates/horizon-client/src/game/native_hooks.rs` (hooks 8–40: block entities, containers, machine ticks, custom machine recipe types, redstone signals, cable/pipe shape updates, player/inventory ticks, `horizon:mod_net` packets, custom GUI screens, server commands).
3. **Pure Rust domain crate (`Cargo.toml` + `src/lib.rs`)**: standalone, fully unit-testable domain logic, energy/EMC math, state machines and `HorizonNativeMod` implementations.

The template is [`mods/example_mod/`](mods/example_mod): `Cargo.toml`, `horizon-registry.toml` (registry page: `name`, `summary`, `description`, `authors`, `license`), `src/lib.rs`, `tests/mod_tests.rs`, `content/horizon-mod.toml`, `native/horizon-native.json` (`schema = 1`, `game = "26.3"`, pinned 40-hex `horizon` and `mixins` revisions, `hooks = 40`), `native/mixins/example_mod/horizon-mixin.toml`.

### The 11-step port process ([`planning/workflow.md`](planning/workflow.md) §2)

| # | Step | Done when |
|---|---|---|
| 1 | **Spec from the Java**: decompile, describe the behaviour citing classes, list blocks/items/subsystems | spec + `<id>.features.json`; feature beads filed |
| 2 | **Scaffold** the three parts above | it builds; check-mods passes |
| 3 | **Code** from the spec only (clean-room) | every Code feature closed |
| 4 | **Check** syntax and logic: `make agent-gate`, parity-critic against spec and Java | clean |
| 5 | **Extract assets**: the original's art and sound from a client build, `origin: original`, credited | every block and item mapped |
| 6 | **New assets**: only what 26.3 needs and the original never had, at its size and palette (`make fleet-gaps`, `make art`) | `make check-mods COMPLETE=1` passes |
| 7 | **Recheck** everything on the whole mod | clean |
| 8 | **Harness (live)**: every block placed (by `/setblock` and a player, every variant), 7 stages, no warnings | every block's harness feature closed (Horizon's own failures don't block) |
| 9 | **Package**: version, commit with the board, pack | committed and packed: **complete, ready for a human** |
| 10 | **Human**: `make play MOD=<id>`, review, push; the workflow publishes a pre-release while original assets remain | pushed |
| 11 | **Own art** (later): replace every original asset; then full releases | 0 original assets |

### Commands

| Command | What it does |
|---|---|
| `./setup.sh` / `setup.cmd` / `make setup` | Set up a fresh clone end to end; `--check` / `make doctor` reports only |
| `make test-mods` | `cargo test` for every crate under `mods/` |
| `make check-mods [MOD=<id>] [COMPLETE=1]` | Validate `.hmod` content and `.hnmod` manifests against Horizon's rules; `COMPLETE=1` also fails on any asset 26.3 needs that is missing |
| `make pack-mods [MOD=<id>]` | Build deterministic `.hmod` and `.hnmod` in `mods/<id>/target/horizon-mod/` |
| `make e2e-setup` / `e2e-mod` / `e2e-all-mods` / `integration-test` | The harness: build Horizon with the mods' mixins, then boot it and run the action plans (exit 3: only Horizon's own problems) |
| `make horizon-baseline` / `horizon-status` | Build and run Horizon alone at the pinned revision / show whether it is healthy |
| `make play [MOD=<id>]` | Open Horizon in a window with the mod (default: all) and a world with every block placed |
| `make decompile JAR=<archive>` | The original's Java in `assets/decompiled/` (spec-writer, reviewer) |
| `make art MOD=<id>` | New art from `mods/<id>/art/` at the original's size and palette |
| `make agent-gate [MOD=<id>]` | rustfmt, clippy `-D warnings`, tests, check-mods and dry run of what you changed (what the stop gate runs) |
| `make agents` / `make agents-check` | Regenerate / check each tool's copy of `.agents/` |
| `make fleet-next [AGENT=…] [MOD=<id>]` | A headless conductor run on one mod, relaunched until it is complete |
| `make fleet-start MOD=<id>` / `fleet-stop` | Start a mod (claim, stories, Horizon check) / let every fleet agent stop |
| `make fleet-task BEAD=<id> ROLE=<role>` / `fleet-inbox` | A subagent takes a bead / the conductor files the reports |
| `make fleet-features MOD=<id>` / `fleet-gaps MOD=<id>` / `fleet-status [MOD=<id>]` / `board` | Beads: features from the spec / from missing assets / progress / regenerate the board |
| `make tekkit` / `direwolf20` / `agrarian` / `all` | Download the modpacks into `assets/` (Agrarian Skies 2 falls back to the public 2.0.6 without `CURSEFORGE_API_KEY`) |
| `make extract-jar JAR=<path> [EXTRACT_OUT=<dir>]` / `make extract-assets [DIR=<dir>]` | Extract textures, sprites, audio, models and scripts from mod archives |
