# Rekkit agent rules

Rekkit ports Java Minecraft mods (Tekkit Classic 1.2.5, Direwolf20 1.4.7, Agrarian Skies 2) to Rust mods for the Horizon engine. Every agent, in any tool (agy, Claude Code, Codex, Cursor, Gemini CLI, Copilot…), follows this file; `CLAUDE.md` and `GEMINI.md` only point here.

- **A role subagent** (the conductor started you on a bead): your prompt and your role file are all you need. Follow the rules below; do not read `.agents/start.md`, the fleet plan or the board.
- **The main session** (a person started you): do `.agents/start.md` now, without waiting to be told. It ends with you conducting one mod to completion.
- Reference (architecture, the 11 steps, every command): `.agents/reference.md`, or `make help`. Read it only when you need it.

## Rules

- One mod at a time. Never start a second epic while one is in progress. `rekkit_core` is the exception that is never started on its own: shared code a mod needs is filed under it (`make core-need`) and built during that mod's run, so the core grows with the mods.
- **Spec first, then the Java.** The spec (`planning/mods/<id>.md`) is an outline of the original: what exists, what it does, which class holds it. Anyone porting a block, item or system reads the outline's sections first, then the original's Java for that piece (`assets/decompiled/` from `make decompile`, never committed), a method at a time. Write our own Rust from it; do not paste Java. The art and sound are the original's until replaced; see `.agents/release.md`.
- **Tickets, small and ordered.** The spec-writers go through the whole decompiled code (one per part, `make fleet-parts`) and turn it into tickets of at most ~200k tokens of work each, with the order between them (`make fleet-tickets` validates and files them). Then the conductor starts one subagent per ready ticket (`make fleet-ready`), many at once. The hooks stop a subagent at 200k tokens of context: it writes its progress notes and a partial report, and a fresh one continues. The 200k is the ticket worker's, not the conductor's: a worker reports in full when its ticket is done and ends (a fresh one takes the next ticket); the conductor, nearing its own limit, waits for every in-flight subagent, files their reports, then clears itself and continues with `make fleet-resume`, without a person.
- **Several versions: merge, newer wins.** When a mod ships in more than one pack (RedPower 2.0pr5b2 in Tekkit 1.2.5 and 2.0pr6 in Direwolf20 1.4.7), the port is the union of every version: each block, item, recipe and system any version has. Where versions share a feature, the newest version's behaviour, numbers and art win (both have the alarm: the 1.4.7 alarm). A feature only an older version has stays, as that version made it (1.2.5's microblocks stay even if 1.4.7 dropped them). One epic and one mod per original mod, never one per version (`.agents/skills/mod-spec/SKILL.md`).
- **Checkpoints.** A role subagent appends one line to `target/fleet/progress/<bead>.md` after each piece it finishes (`make fleet-task` says so and shows an interrupted predecessor's work). A conductor taking over runs `make fleet-resume MOD=<id>` (`make fleet-start` prints it) and restarts interrupted subagents rather than their steps.
- Template: `mods/example_mod`. Copy its shape; do not invent new layouts.
- Shared code lives in `crates/rekkit_core` (not under `mods/`). Use it instead of redefining energy, stacks, tanks, grids, side config, multiblocks or frequency keys.
- Never put `Cargo.toml` or `.rs` files under `mods/<id>/content/`.
- Native bundles (`native/mixins/<id>/horizon-mixin.toml`) take only `id`, `version`, `priority` under `[mod]` and need at least one `[[injection]]`; `make check-mods` enforces what `horizon-mixins` enforces.
- Never edit `horizon/` (git submodule). An engine gap is a Beads bug labelled `horizon` (subagents: a follow_up in the report).
- Every native hook checks its own namespace (`<id>:`) before acting.
- Only edit paths you own (your role file says which). Report anything else to the conductor.
- Complete = steps 1–9 closed: `make agent-gate MOD=<id>`, `make check-mods MOD=<id> COMPLETE=1`, parity-critic's Check and Recheck, and the live harness (`make e2e-mod MOD=<id>` and `make e2e-all-mods`: every block placed by `/setblock` and by a player in every variant, every item found in the mod's creative tabs, no WARN/ERROR beyond `planning/harness-allowed-warnings.txt`, which only a person edits).
- **Local models** (opencode, or any tool, on Ollama, LM Studio or llama.cpp; not cloud models) **never start subagents**. The one session runs on the model opencode has selected (`/conductor`) and does every role itself, one ticket at a time, from `.agents/agents/<role>/agent.md`, still writing each report to `target/fleet/inbox/`. The opencode plugin blocks the `task` tool (set `REKKIT_ALLOW_SUBAGENTS=1` only for a cloud model run in opencode). `make fleet-local` always reports 0 subagents.
- **The port is the original, not a stand-in.** The outline (`planning/mods/<id>.features.json`) gives each block's and item's attributes (a solar panel generates in daylight and stores energy); its porting agent writes its contract file (`planning/mods/<id>.contract/<name>.json`, from the Java): shape, facing, face sprites, GUI slots, sprite, stack size, durability, and a scenario testing each attribute. Every attribute has a test level, and an attribute no scenario of its level tests, or one whose scenario fails, is a blocker: 1 placement & hitbox, 2 item use, 3 block function (energy, fuel, storage, GUI slots), 4 interaction with other blocks, 5 persistence (chunk reloaded), 6 automation & sides, 7 all mods together (the mod-spec skill, Test levels). `make contract-check MOD=<id>` compares the models and textures with the original's pixels; the harness checks outlines, GUI slot positions and scenarios. A vanilla or swapped texture, one texture on every side, a cube where the original is thin, a stock `generic_9x3` grid or a machine that does nothing is a bug, never done; `make fleet-contract MOD=<id>` files each one and the stop hook holds the mod open while any remains.
- New art only for what the original never had (`make fleet-gaps`): SVG or `.pixels` in `mods/<id>/art/`, built by `make art MOD=<id>` at the original's size and palette.
- The Makefile picks Python 3.11+ itself; outside make use `$(scripts/fleet/python.sh)`.
- Never `git push`, `gh release`, `minisign`, change the submodule, `git reset --hard`, `--force` or `rm -rf`. A human does those (the hooks in agy and Claude Code block them; elsewhere it is on you). Releases are signed and published by `.github/workflows/release-mods.yml` after a human pushes.
- **Versions bump themselves.** When a mod or `rekkit_core` changes, `make version-sync` (run by the stop gate, `make fleet-inbox` and `make agent-gate`) moves it one patch version past its last commit, in lockstep across `Cargo.toml`, `content/horizon-mod.toml`, `native/horizon-native.json` and `native/mixins/<id>/horizon-mixin.toml` (the core: its `Cargo.toml`). Work done before the next commit is bundled into that same version. Never edit a version by hand.

## Context budget

Everything you read stays in your context and is paid again on every later step, so read narrowly.

- Decompiled Java, after the spec: `make java-outline DIR=<decompiled> [GREP=<name>]`, then `make java-show DIR=<decompiled> MEMBER=<Class#method>`; never a whole class (the hooks refuse reads of more than 200 lines of it).
- A spec: `make spec-toc MOD=<id>`, then `make spec-show MOD=<id> SECTION="<heading>"` for the sections your work needs.
- Where things are for a mod: `make fleet-context MOD=<id>` (state, spec, original archives in every pack, decompiled folders, files), not `ls`/`find` sweeps.
- Run commands; do not read scripts to learn what they do (`make help`, `<script> --help`). Do not re-read a file you already read unless it changed. Read files by line range when you need part of one.
- Long command output: keep the end (`2>&1 | tail -40`), or grep for what you need.
- Done means stop: write your report (subagents) or go to the next step (conductor); no recap of what you did.
